- `new_from_now`：从现在起的新材料；
- `historical_batch`：一批历史材料；
- `mixed_uncertain`：新旧混合，多数逐份日期不清楚。
- `unknown`：现有证据不足以确定本组新旧属性。

先查看原件、现有记录和家长本次已给的说明；能确定本组属性就直接记录，不重复询问。若新旧归属或大致时间不清且会影响截止事项、考试归属、教学进度或事实先后，再向家长询问一次能确认的最粗范围；可回答年份、月份范围、学期、“某日以前”或“不知道”。无须据此判断的材料可记`batch_mode: unknown`和`parent_observation_range: unknown`继续处理。家长给出的概数身份固定为`parent_observation`，不得批量写入每份材料的`material_date`。

每份材料必须区分：

- `received_at`：文件实际进入当前处理流程的日期、时刻与时区；
- `material_date`：原件明确显示、家长对该材料明确说明，或按下述“收件当年”默认规则补足年份的日期；
- `parent_observation_range`：材料索引中这一组材料的大致历史范围。

**modifier**：GPT-6（OpenAI Codex Agent，Default 模式；小版本未暴露）

**date**：2026-10-20

v0.1 只为孩子需要逐题作答的练习题、作业题和试卷题生成“家长作业前置卡”：实际题面已提供，或能够依据通知从已入库教材、练习页、附件中准确定位题目时，处理材料的同时按需生成。绘本朗读／还课、知识点页、课文或句型示例、单纯阅读／背诵／预习等，即使是老师指定任务，也不自动制作前置卡；照常归档、转录、关联待办，并按明确请求制作朗读打印页等对应交付。若这些材料另附需要孩子作答的实际题目，只对那些题目按本节处理。它用于让家长提前理解题目并在孩子临时求助时有可直接使用的支持，不等同于给孩子布置额外练习。只有作业名称、课次、页码或泛泛的指导示例，而实际题面尚未提供、现有资料也无法定位时，记录缺少什么并提示家长；不因一张通知截图自动制作前置卡。通知附的示例可作为参考资源保存，不能冒充孩子要作答的题目。家长明确要求另做参考资料时，可按该请求单独交付，并标明不是老师另布置的作业；不按本节自动生成题目型前置卡。

前置卡 Markdown、按需生成的 HTML 与仅供卡片显示的配套资源统一放在`03-完整转录/家长前置卡/`，沿用材料编号命名；逐件材料记录与完整转录放在`03-完整转录/材料记录/`，独立核对结论放在`03-完整转录/核对记录/`，`材料索引.md`留在`03-完整转录/`根目录。生成或移动后检查卡片到原图、逐件转录和核对记录的相对链接。

对已确认需要孩子作答的简单一题或少量文字题，先在会话中给出可直接使用的答案与引导，并用 Markdown 保存长期记录；不为单张通知或一条提示默认制作 HTML。试卷和多题、多页作业需要按题号查看原图、切换核对／引导或反复定位时，同时提供可检索的 Markdown 与可在本地浏览器打开的 HTML；触发条件是**逐题查看的实际需要**，不是“试卷”或“作业”的文件名。HTML 使用三栏题卷联动布局：左栏按原卷题号导航和搜索，中栏展示对应原卷页及当前题目位置、可放大，右栏按“可照读的专属引导词 → 对应参考答案／示例 → 核对要点”的顺序展示。左栏只放题号或简短场景名及必要状态，用于定位和切换；不在导航中展开完整答案、引导词或核对内容。切换题目后，右栏从引导词顶部开始显示。含孩子作答时，在对应题上区分已确认不符、字迹待核、题目有歧义与已核相合；不能只把 Markdown 表格排成普通列表页替代该布局。嵌入原卷图片时使用本地相对路径，验证页面和图片引用可用。两种格式同时存在时同步核查，避免答案或状态分叉。

### 一份 HTML 合用核对与引导

含孩子作答且已完成独立双路核对时，优先在同一份 HTML 中按**同一道题**切换“答案核对”和“前置引导”，不另造一份容易与题号、原卷和参考答案脱节的错题页面。两种视图共用左栏题号、搜索、状态筛选和中栏原卷定位；切换视图保留当前题号、原卷页和缩放状态。

- **答案核对视图**：默认让家长看到当前需关注题。题号以红色标已确认不符或回答不充分、橙色标待核、绿色标已核相合，并同时显示文字状态，不只靠颜色。右栏先列孩子原答、核对结论、原题或教材依据与未决处；参考答案默认收起。已订正但仍需复核的状态单列，不把初错覆盖成“从未错过”。
- **前置引导视图**：右栏逐题提供可照读的专属引导词、对应参考答案和核对要点；必要时增加“先问—再提示—最后兜底”。语文开放题同样需要引导，示例答案须注明不唯一。引导视图供家长备用，不表示已经决定对孩子讲解或展示答案。
- **数据边界**：核对状态只能来自已冻结并汇合的独立核对、家长确认或教师反馈；前置卡的参考答案与引导词不能反过来决定核对状态。新照片、订正或教师复批到来时，先更新事实链与核对记录，再同步 HTML 和 Markdown 的状态、原答与引导。
- **原卷定位**：按当前展示的每张原图逐题校准框选区域，不能用整页共用的粗略纵向百分比冒充精确题位。点击题号时只滚动原卷视窗和左侧题目列表，不能让题目列表的定位操作把整个浏览器页面滚走；选中区域应落在视窗可读位置。换图、裁图、改变页面布局或缩放后复查坐标。
- **交付检查**：在浏览器检查四类典型题位：页首、页中、页末及至少一处跨页切换；逐项确认框选与原题对应、滚动停在该题附近、两视图切换保持题号、参考答案与专属引导仍可见。原卷图片、HTML 内链和 Markdown 链接均须可打开。

前置卡至少包含：

1. **题目在练什么**：用简短语言说明知识或表达目标；
2. **参考答案／答案池**：提供一套可实际使用的答案；开放题给出多个合理示例，并注明答案不唯一。原图或老师给出的例句与 AI 另写的可替换示例分列，不把原图的几个例句重复展示后称为“新增答案池”；
3. **每个答案对应的引导词**：答案与引导词逐项配对，每个答案都有能单独把孩子引向该答案的可照读话术；必要时再为单个答案细分“先问—再提示—最后兜底”；
4. **核对要点**：说明什么算答到要求、容易混淆什么；
5. **来源与置信度**：区分教材原文、标准答案、AI生成示例和待确认信息。

处理边界：

- 前置卡默认供家长使用，必须和孩子的原始作答、老师标准及忠实转录分开；
- 前置卡不是后续作业或试卷答案核对的证据来源，不得作为任何一条独立核对链路的参考答案；
- 家长可以直接获得具体答案，不要求家长先自行解题；
- 不能只为整道题提供一套通用引导词，也不能只写“启发孩子思考”等空泛建议；答案池中的每个候选答案都必须有自己的具体引导词；
- 开放题不得把示例包装成唯一标准答案；客观题没有可靠依据时必须标注不确定，不得编造答案；
- 自动生成前置卡不代表已经决定给孩子讲解、展示答案、增加练习或安排复查，这些动作仍由家长决定；
- 只有通知过于笼统、题目不可见且现有教材无法准确定位时，才不生成答案，并明确缺少什么材料。

## 答案独立双路校验

凡需要判断孩子答案`pass`或`mismatch`的作业、试卷、默写和练习，必须完成两条相互独立的核对链路。增加第二层的目的不是让同一结论被复述一次，而是降低识图、运算、数位、题意和开放题标准上的共同误判。

### 独立性要求

1. **核对A**只读取原始题目、孩子原始作答、老师可见批改及必要的教材或权威答案，自行解题并记录依据；
2. **核对B**由另一独立Agent执行，只接收与核对A相同的原始证据，不接收核对A的答案、推理或结论；
3. 核对A和核对B在各自结论冻结前，均不得读取家长作业前置卡，也不得把历史转录中的旧`pass`／`mismatch`当作答案依据；
4. 若当前执行者已经读取过前置卡或旧核对结论，不得把自己的再次复述算作独立核对；应启用隔离上下文的Agent重新完成该路；
5. 每一路都要记录答案、关键依据、置信度和无法确认项。数学题须独立重算，并对数位、单位、往返、边界值、题目要求的步骤数等高风险点做反向检查。

### 汇合与冲突处理

两路结论冻结后才能汇合：

- A、B一致：形成暂定核对结论；随后与前置卡比较，检查前置卡是否需要修正；
- A、B不一致：不得按多数、旧记录或前置卡直接裁决，必须回到原图和题面定位分歧，必要时查教材、教师答案或请家长核对；冲突解决前状态记为`pending_verification`；
- A、B一致但与前置卡不一致：优先重新审查前置卡。前置卡只能暴露冲突，不能推翻或确认两路核对；
- 前置卡、核对A、核对B的生成者、时间和依据应分别记录，不能把三者合并成一个来源；
- 只有独立双路校验完成且冲突已经解决后，才能将内容结论写为最终`pass`或`mismatch`并同步错题台账。

若运行环境确实无法启用独立Agent，可以先完成核对A，但不得把单路结果标为最终结论；应记录`pending_verification`，等待独立校验补齐。

本规则适用于新处理的孩子作答材料，以及以后因新证据、复查或更正而重新打开的旧材料；不要求在没有触发事项时一次性回查全部历史记录。

## 初次错误到订正的连续记录

**modifier**：GPT-6（OpenAI Codex Agent，Default 模式；小版本未暴露）

**date**：2026-10-19

孩子对同一份作业先作答、经AI核对或家长提醒后再修改时，将各环节关联为一条时间链：初次作答原件及答案 → 独立双路核对结果 → 家长提醒或老师意见（注明信息来源）→ 孩子订正原件及可见变化 → 订正后独立双路复核 → 老师复批或最终反馈（若有）。不得用订正答案覆盖初次答案，也不得因初次错误已订正而删除历史错题；错题台账保留初错，另记订正时间、内容、复核状态和复批状态。

收到同一纸张的再拍照片时，须逐处比较涂改、补字、批注、评分和裁切范围；有任一新增内容就作为不同版本保存和关联，不按完全重复件删除。家长对“因提醒而修改”等过程的说明标为`parent_observation`，照片可见的笔迹变化标为`source_fact`，两者不可互相冒充。

对家长报告“已订正”与照片可见“改过字”可先记录事实，但订正后内容的`pass`或`mismatch`仍须重新完成本节的独立双路答案核对。若双路无法完成，记`pending_verification`；若老师尚未复批，记`not_evidenced`。向家长列“目前错题”时区分初次错误、已见订正但待核、订正后仍错及从未见订正，不把历史初错误写成当前仍未修改。

## 老师通知关键字段的独立双路识读

老师通知、作业卡、群截图或要求附件中，凡会决定孩子要做什么、何时做、做多少或后续如何跟踪的字段，也须进行独立双路原件识读。包括学科、第一／第二等单元编号、课次、题目或页码范围、听写／过关范围、日期与截止时间、提交方式。即使没有孩子作答，也适用本规则；不能因其是“通知”就只做单路识图。

1. 核对A与独立Agent核对B分别直接看同一原始截图或文件，逐字摘录关键句，并注明原件位置、字段与识别置信度。两路冻结前不得读取对方结论；B不得把既有转录、索引、事件或待办作为原文依据。已经读过旧记录的执行者须重新回看原件并标明这一背景，不把旧文字重复一遍当作原件核对。
2. 汇合时逐字段比对，特别反查范围词和编号，如“一二单元／二单元”、否定词、日期、页码和提交方式。两路不一致、原件模糊或与现有记录冲突时，回到原件定位；仍无法确认则记`pending_verification`并向家长提出最小核对问题。冲突未解决前，不把该字段写成最终`source_fact`，也不据此建立确定范围的事件或待办。
3. 两路一致且冲突解决后，记录A／B执行者、时间、各自所见原文和汇合结果，再同步材料转录、学习事件、待办、教学进度与索引。通知本身未明确的题型、日期或细目继续记`unknown`。
4. 家长指出通知转录与原图不符时，立即重新打开原件核对争议处；不得仅检索并复述已有转录。更正时保留错误来源和更正日期，修正所有受影响的关联记录。

若无法启用独立Agent，可先保留单路候选识读和原件路径，但关键字段状态为`pending_verification`，不得当作已双路确认的通知范围。新规则适用于新处理通知及因新证据、质疑或更正而重新打开的旧通知；不要求无触发事项时批量回查历史通知。

## AI编制练习材料的交付前双路核对

家长已确认制作的练习题、复习页、听写默写打印页及配套答案，在交付前执行两路内容核对。修改已交付材料时，对修改项及其相关内容重新核对。此规则不授权AI自行决定孩子需要加练。

1. 制作方作为核对A，直接对照教材原页、老师通知原件及必要的权威来源，逐项检查范围、课次、题目和答案、词语与字表完整性、拼音及多音字语境、学生页与家长答案的顺序和对应关系；另检查排版与学生页是否泄露答案。
2. 独立Agent作为核对B，接收相同的原始来源和待交付的学生页、家长答案页，自行逐项核对。B在冻结结论前不读A的结论、生成脚本中的预设答案、旧核对记录或旧转录；不能把拼音工具的默认结果当成最终依据。
3. 两路分别记录检查范围、发现的问题、来源页码和未确认项，然后汇合。差异回到教材或通知原件查证；有确定错误则修正，并重新核对受影响的学生页和答案页。尚无法确认的项目要显著标明并向家长说明，不能把单路检查称为已双路通过。
4. 内容核对后，渲染最终PDF逐页查看文字、拼音、格子、换行和裁切；重开最终文件检查内容可读。发现错误时不得仅修改答案页或只修改学生页。

## 未来事项

老师通知、作业布置或其他材料中出现未来有明确日期的默写、测验、交材料、带物品等事项时：

- 直接建立用于等待事项发生和结果回流的事实型待办；
- 同时把“是否需要事前准备”标记为待询问；
- 不得因存在未来事项就自动创建复习、练习或讲解安排；
- 按`事件与待办规则.md`在到期前每日沟通中询问一次，直至家长明确关闭本次准备、确认已经完成准备，或事项已经发生。

老师已预告测验或单元过关但尚未公布日期时，也须建立准备询问；每日相关沟通规则及关闭口径见`事件与待办规则.md`“日期未公布的测验与单元过关预告”。

## 成套资料的缺号检查

- 文件名、封面或老师通知显示同一系列按单元、周次、课次、页码等编号时，处理本批材料前先检索该系列在收件箱、教材库和原始材料中的已有文件及索引。例如收到`U2—U8知识点`，须检查是否已有`U1知识点`。
- 列出可证实的编号范围、已收到编号、缺号和来源依据。只把系列内部的空档、已知起始编号的缺口或通知明确提到的附件列为待核对；不凭最大编号推断老师一定发过全部较早或后续单元。
- 发现缺号时，在本次相关沟通中主动提醒家长，并说明缺少原件会影响哪些关联或计划。缺号记为`本地未找到／待核对`，不等同于老师未发、孩子未贴、未做或不会；家长确认已使用但未入库时，分别记录使用事实和原件缺失。
- 家长补入后归档并更新系列完整性、相关通知、学科进度与计划索引。若家长说明暂不提供或没有该件，保留其说明，不反复索取。

## 原件处理

**date**：2026-10-19

- 原件从收件箱移动到相应的`02-原始材料/`分类目录，不额外复制重复文件。
- 记录原始文件名、接收时间、归档路径、文件类型和可用时的文件哈希。
- 非重复的图片、PDF和音视频默认保留；删除或覆盖须由家长明确指定。
- 初始化时询问一次持续授权：对确认内容完全重复的文档、图片、音视频等，是否只保留质量更好、内容更完整的一份并记录舍弃信息。家长回答`yes`后可持续执行，不必逐次询问；回答`no`或尚未确认时保留各版本并标记待核对。该授权只适用于确认重复件，不追溯清理旧归档，也不授权删除非重复原件。
- 先以哈希识别字节完全相同的文件。哈希不同但疑似同一内容时，须核对文档页数与全文／图像内容、视频画面与音轨及完整时长等，确认没有独有内容后才按重复件处理；仅文件名相近、首帧相同或时长相同不足以判定。无法确认时保留各版本并标记`疑似重复，待核对`。
- 已确认重复时优先保留内容完整、清晰度高、可读取性好的版本；质量相同则优先保留已入库且被其他记录引用的版本。更新所有受影响的路径和索引后再移除多余副本，不静默覆盖保留件。
- 在保留件的材料记录中追加舍弃副本的原始文件名、接收时间、类型、哈希、与保留件的重复判定依据及处理日期。若副本尚在收件箱，不为它另建一份材料记录；已存在的不同版本若内容有实质差异，均按独立材料保留。

## 信息身份

材料记录必须区分：

- `source_fact`：可从原件直接观察的事实；
- `child_report`：孩子的口头描述；
- `parent_observation`：家长的观察或判断；
- `ai_inference`：AI提出的解释或候选关联；
- `confirmed`：经家长或后续材料确认的信息；
- `unknown`：当前缺失或无法辨认的信息。

## 孩子作答类材料的完整转录

凡材料包含孩子本人作答，均必须生成完整忠实转录，包括但不限于试卷、练习、作业本、作文、默写、听写和订正稿。不得用内容摘要、错题摘录或结论性描述代替完整转录。

完整忠实转录至少保留：

- 原有标题、题目或写作题目；
- 孩子的原句、原答案、可辨认步骤、段落和标点；
- 可见错别字、病句、涂改、删除、增补和空白；
- 老师批改符号、批注原文及其对应位置；
- 无法辨认、遮挡、裁切或含义不明的位置。

忠实转录不得按正确答案、老师意见或AI建议静默改写。润色稿、订正建议和结构化分析必须另设章节，并与原始作答明确区分。无法辨认项仍按本文件的核对闭环处理。

不含孩子作答的通知、要求附件、参考范例和教材页，可以根据任务提取必要信息；若其逐字内容会影响范围、格式、答案核对或后续执行，则仍须完整转录。

## 无法辨认项的核对闭环

“无法辨认”只表示AI不能从现有原件中可靠确认，不表示该信息无需处理。每份材料识别完成后，AI必须汇总无法辨认、被遮挡、被裁切或含义不明确的项目，说明它在原件中的位置以及可能影响什么，并询问家长是否愿意查看或补充。

处理状态依次为：

```text
识别不确定
→ pending_confirmation（已提醒家长，等待选择）
├── 家长补充 → confirmed_by_parent（保留AI原识别，并追加家长确认内容、日期和来源）
├── 家长提供更清晰材料 → 根据新原件重新识别并关联原记录
└── 家长明确不看／不用管 → unresolved_closed（保留“不作推定”，不再主动追问）
```

- 不得只在文件中写“不作推定”而不向家长提示。
- 同一份材料有多个不确定项时，优先合并为一次清单式询问，避免逐项打断。
- 家长补充的信息必须标记为`parent_observation`或`confirmed_by_parent`，不能改写成原件直接可见的`source_fact`。
- 家长确认后，保留原始识别记录和不确定性说明，在其后追加确认结论，不静默覆盖。
- 家长明确选择不核对后，才可将该项关闭为“不作推定”；以后有新材料提供相反证据时可以重新打开。

## 作业检查与闭环

材料类型为作业且存在老师通知、题目要求或其他明确标准时，完整转录之后必须增加“作业检查”，不能把“已经拍照归档”当作作业闭环。

作业检查至少分成四层：

1. **范围完成情况**：通知要求的项目是否都有完成证据；
2. **格式符合情况**：本子、位置、书写布局、是否需要注释等形式要求是否符合；
3. **内容正确性**：将孩子原始书写与教材、原题或老师提供的标准逐项对照；
4. **批改与反馈**：记录老师的分数、等级、日期、批注和订正要求。

每项使用以下结论之一：

- `pass`：现有证据确认符合；
- `mismatch`：现有证据确认与要求或标准不一致；
- `not_evidenced`：现有照片没有覆盖，不能判断完成或未完成；
- `not_applicable`：该项不属于本次作业要求。
- `pending_verification`：两路核对尚未完成或结论冲突，暂不判定对错。

处理边界：

- `mismatch`是材料对照事实，可以直接记录；错误原因、是否粗心、是否需要讲解或练习仍需家长确认。
- 照片没有覆盖某项时，只能记为`not_evidenced`，不能直接判定“未完成”。应请求家长核对或补充材料。
- 同一张照片中出现的不属于本次作业范围的旧内容，可以记录为“附带发现”，但不能计入本次作业完成与否。
- 作业闭环必须明确记录：是否完成、是否符合形式要求、是否存在内容错误、尚缺什么证据。收到材料但尚未完成这些检查时，状态不得写成“已闭环”。
- 家长补充的完成情况或批改结果要标明`confirmed_by_parent`及日期，不改写成原件直接可见事实。

## 错题台账

AI编制家庭练习的还课完整转录、纠错及错题来源区分，另见[AI家庭练习还课与来源区分规则](AI家庭练习还课与来源区分规则.md)。家庭练习错题单独建账，与学校作业／测验统计分开；AI出题、答案或识别判定错误单独更正，不能计入孩子错题。

数学学校新材料和AI家庭还课完成内容核对后，均同步对应来源台账与数学统一错题池的引用／回访关联。更新不得依赖家长另行提出出题请求；下一轮组题须同时查看两类来源、最近正确表现和教材覆盖计划。来源事实只存一处，池中引用并按材料、题号和作答版本去重。

作业或试卷在内容核对中出现已经确认的`mismatch`时，除在原材料完整转录中保留上下文外，还应同步登记到对应学科的错题台账，避免以后依赖临时全文检索重新捞取。

错题台账至少记录：来源材料与题号、题目要点、孩子原始答案或步骤、核对结果、订正状态、老师复批状态、知识点和错误原因状态。

- 台账是事实索引，不能替代原材料的完整转录；需要完整题面和上下文时仍回到来源材料。
- 已订正不能覆盖原始错误；在原记录后更新`corrected`或`teacher_verified`状态。
- 错误原因默认记为`unknown`。粗心、不会、理解偏差或能力薄弱等判断仍须家长确认。
- 登记错题不自动生成重做、讲解、练习或复查安排；这些属于判断与干预型动作。
- 格式问题、范围问题和无法确认的识别结果不混作内容错题，可在来源材料中另行保留。
